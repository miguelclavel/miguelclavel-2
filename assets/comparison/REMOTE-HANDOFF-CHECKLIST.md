# Remote developer handoff checklist

Use this checklist for a distributed implementation team.

## Component definition

1. Name and purpose of every component

2. Anatomy and child elements

3. Required and optional properties

4. Atlas tokens and approved variants

5. Content and data dependencies

## Responsive behavior

1. Breakpoint behavior matrix

2. Sticky header and first column rules

3. Horizontal overflow behavior

4. Card or collapsed row behavior on narrow screens

5. Reading and focus order

6. Text zoom and browser resizing expectations

## Interaction states

1. Default, hover, focus, selected, and disabled

2. Sort and filter behavior

3. Expand and collapse behavior

4. Pagination or comparison limits

5. Loading, empty, partial data, and error states

6. Start, middle, and end of horizontal scrolling

## Data and content contract

1. Required fields

2. Optional fields

3. Missing value behavior

4. Character limits and wrapping

5. Supported cell content types

6. Product count limits

7. Editorial and legal content requirements

## Accessibility

1. Semantic structure

2. Table captions and header relationships

3. Keyboard order and controls

4. Focus visibility

5. Screen reader labels and announcements

6. Contrast and noncolor indicators

7. Reduced motion behavior

## SEO and discovery

1. Crawlable content

2. Server rendered critical information when supported

3. Descriptive headings and links

4. No duplicate hidden responsive content

5. Structured data validation when appropriate

## Quality assurance

1. Acceptance criteria for each component and state

2. Test data for long names and missing values

3. Desktop and mobile browser coverage

4. Keyboard and screen reader checks

5. Visual comparison against the approved design

6. Content, SEO, and analytics review

7. Decision log and unresolved questions

8. Final design review after implementation

## Asynchronous communication rule

Every annotation should explain the expected behavior, the reason for the rule, and the acceptance criteria. This lets an overseas developer continue implementation without waiting for the next meeting.
